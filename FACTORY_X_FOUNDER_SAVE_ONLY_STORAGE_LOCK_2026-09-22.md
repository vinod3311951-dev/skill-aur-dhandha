# FACTORY X — FOUNDER SAVE-ONLY AND STORAGE PROTOCOL
Effective: 2026-09-22
Status: LOCKED
Scope: All current and future Factory X products

## Purpose
Prevent founder storage overload across the 18-product lifecycle while preserving complete operational evidence in GitHub and Factory X chat history.

## Manual Save Rule
The operator may suggest a manual founder save only in these cases:

### A. Per product at FX-25 Freeze
Produce ONE consolidated `Product Final Record` per product.

It must contain:
- FX-25 packet summary
- founder functional check result
- final URL
- final commit hash
- IP/copyright register summary
- any open IP/trademark gaps requiring later resolution

Portfolio target:
- 18 Product Final Record files total across the 18-product portfolio.

### B. Portfolio authority lock
When a genuinely new Factory X authority is locked, preserve the authority file in GitHub.
Manual founder saving is exceptional/rare and must not be suggested routinely.

## Everything Else
Do NOT suggest manual saving for:
- individual FX-XX completion packets
- QA records
- audit packets
- BrowserStack/Playwright records
- intermediate repair files
- retrofit logs
- staging screenshots
- diagnostic reports
- deployment evidence

These remain in:
- GitHub, committed by the operator
- ChatGPT Project conversation/history where applicable

## Storage Location Protocol
Primary future manual-save destination:
- Telegram Saved Messages

Per-product final records:
- Telegram Saved Messages

Authority files:
- GitHub is the authoritative storage location and operator commits them there.

Gmail:
- existing files remain as historical archive
- do NOT send or recommend new product files to Gmail from 2026-09-22 onward

## Operator Language Rule
Only say or recommend "save this" when the item qualifies under this locked protocol.
Do not create founder-save burden for routine Factory X evidence.

This directive does not modify any product stage, audit score, audit rubric, or existing locked product authority.
